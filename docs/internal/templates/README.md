# docs/internal/templates — 문서 골격

Phase마다 반복해서 쓰는 문서의 **골격(템플릿)** 을 둔다. Phase 당 문서는 **3개**다(`CLAUDE.md` 4절).

> **v2 (2026-09-16)**: 템플릿을 6종에서 3종으로 줄였다. 요구사항정의서는 설계서에 흡수하고, 테스트결과서·TechSpike·SelfReview 는
> 실측기록 하나로 합쳤다. 근거: `docs/internal/qa/질의응답_방법론개정.md`

## 사용법

1. 필요한 템플릿을 복사해 `CLAUDE.md` 9절 파일명 규칙(`[P<N>_]<DocType>_<Topic>.md`)에 맞춰 이름을 바꾼다.
2. 머리말 불릿 메타 블록을 채운다 (상위 문서·절번호, 규칙, 작성일, 작성 LLM, 상태/결과).
3. `> 안내:`로 시작하는 인용 블록은 **작성 지침**이다. 채우고 나면 지운다.
4. 꺾쇠 자리표시자는 남겨두지 않는다.
5. 절 번호와 순서는 바꾸지 않는다 — 사람이 같은 자리에서 같은 내용을 찾을 수 있어야 한다. 절을 추가할 때는 끝에 붙인다.

## 템플릿 목록

| 템플릿 | 만들어지는 문서 | 위치 | 순서 | 무엇을 위한 문서인가 |
|---|---|---|---|---|
| `템플릿_설계서.md` | `P<N>_설계서_<Topic>.md` | `docs/` (제출물) | 1 | 유지보수·인수인계 — 요구사항과 **설계 판단**(왜 + 기각 대안) |
| `템플릿_실측기록.md` | `P<N>_실측기록_<Topic>.md` | `docs/internal/` | 3 | 트러블슈팅 근거 — 외부 서비스의 **실제 출력**, 재작업, 남은 위험 |
| `템플릿_학습가이드.md` | `P<N>_학습가이드_<Topic>.md` | `docs/internal/` | 보조 | 개발을 모르는 사용자의 이해 — 직접 실행하는 실습과 예상 질문 |

## 공통 규약 — 머리말 메타 블록

모든 문서는 `#` 제목 바로 아래에 **불릿 목록**으로 메타를 둔다 (YAML front-matter가 아니다).

```markdown
# P1 설계서 — ChannelListing

- 상위 문서: `docs/scope-definition.md` 2.2절, `docs/설계서_Architecture.md` 2절
- 규칙: `CLAUDE.md` 4절 1단계 산출물. 다음 산출물은 코드+테스트 → `docs/internal/P1_실측기록_ChannelListing.md`
- 작성일: 2026-09-16 / 작성 LLM: Opus 5
- 상태: 초안
```

- **상위 문서에는 절번호까지** 적는다. 값을 옮겨 적지 말고 절 번호로 링크한다(`CLAUDE.md` 5절 단일 출처).
- 개정은 제자리에서 하고, 제목 아래에 `> **v2 개정 사유 (YYYY-MM-DD)**: …` 인용을 **최신순으로 누적**한다. 이전 판 서술을 지우지 않는다.
- FR 번호대: P0 = FR-1~99, P1 = FR-101~199, P2 = FR-201~299 …
