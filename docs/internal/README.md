# docs/internal — 내부 자료

**제출물이 아닌** 문서를 둔다. 제출물은 `docs/` 최상위의 `scope-definition.md`·`설계서_Architecture.md`·`P{N}_설계서_*.md` 이며 우리 판단의 근거만으로 서술된다.
여기 있는 것은 그 판단에 이르기까지의 실측·점검·학습 자료다. 지우지 않는다 — 어떤 결정이 어떤 실측을 거쳐 나왔는지 추적할 수 있어야 한다(`CLAUDE.md` 10절).

> **v2 (2026-09-16)**: 방법론 개정으로 파일이 줄었다. `P{N}_검토서_TechSpike`·`P{N}_테스트결과서`·`P{N}_검토서_SelfReview` 를
> `P{N}_실측기록_*` 하나로 합쳤고, `설계서_Agents.md`(서브에이전트 폐지로 대상 소멸)와 템플릿 3종을 지웠다.
> 근거: `docs/internal/qa/질의응답_방법론개정.md`

## 파일

| 파일 | 무엇을 위한 것인가 | 작성 시점 |
|---|---|---|
| `P{N}_실측기록_<Topic>.md` | **트러블슈팅 근거** — 실행 환경, 외부 서비스의 실제 출력, 완료 기준 대조, 재작업, 남은 위험, 재현 명령 | Phase 마다 |
| `P{N}_학습가이드_<Topic>.md` | **사용자 이해** — 직접 실행하는 실습, 설계 결정 설명, 예상 질문 | Phase 마다 |
| `학습가이드_문제해결.md` | **사용자용 문제 해결** — 화면 증상 → 확인 → 조치. 개발 지식 없이 읽는다 | 2026-09-16 |
| `검토서_트러블슈팅.md` | 개발자용 장애 이력 누적 `T-001~`. "이 오류 본 적 있나"를 찾는 곳 | 2026-09-14~ |
| `검토서_Prototype.md` | Phase 1 전 E2E 프로토타입(`prototype/e2e-slice`) — 실행 방법·실측·P1~P3 인계 | 2026-09-15 |
| `용어집.md` | 유튜브·자막·STT·저장·방법론·배포 용어 (컴공 졸업생 눈높이) | 2026-09-14 |
| `templates/` | 문서 골격 3종 + 사용법 | 2026-09-14 |
| `qa/` | 사용자 요청 원문과 결정 (`qa/README.md` 색인) | 2026-09-14~ |

현재 있는 Phase 문서: `P0_실측기록_Common.md`, `P0_학습가이드_Common.md`.

## 여기 없는 것

- **작업 프롬프트** — 만들지 않는다(방법론 v2). 사용자 요청 원문과 결정은 `qa/` 가 담는다(`CLAUDE.md` 10절).
- **`history/`** — 세션 작업 기록. **사후에 고치지 않는다**(기록 위조).
- **`data/`** — 자막 원본·오디오·모델·DB. 저작물·용량 문제로 git 미추적. 재현 명령은 각 실측기록의 마지막 절.
