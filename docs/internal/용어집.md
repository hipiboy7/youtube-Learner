## 1. 유튜브·목록

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **롱폼 / 숏폼** | 일반 가로 영상 / 세로 짧은 영상(Shorts). 유튜브는 채널 페이지에서 **Videos 탭**과 **Shorts 탭**으로 나눠 보여준다 | `VideoKind = long / short`. **탭 소속**으로 판정한다. 길이로 판정하지 않는다(롱폼 탭에 42초 영상, 숏폼은 최대 3분) |
| **탭 URL** | `https://www.youtube.com/@핸들/videos`, `/shorts`, `/streams` | yt-dlp에 탭 URL을 넘기면 그 탭의 영상만 나열한다. 플레이리스트 URL(`UU…`, `UUSH…`)은 쓰지 않는다 |
| **핸들 / 채널 ID** | `@sebasi15`(바뀔 수 있음) / `UCgheNMc3gGHLsT-RISdCzDQ`(불변) | 정체성은 채널 ID(`yt_channel_id`). 핸들은 표시용 |
| **flat 추출** | yt-dlp가 목록 페이지만 읽고 영상별 페이지는 열지 않는 모드(`extract_flat`) | 빠르다(60건/2.4초). 대신 `upload_date`가 없고 숏폼은 `duration`도 없다 → **메타 보충** 필요 |
| **메타 보충(metadata fetch)** | 영상 1건씩 열어 길이·업로드일·언어·자막 트랙 목록을 가져오는 단계 | 증분으로 한다(이미 보충된 영상은 건너뜀). 자막 트랙 확인도 같은 요청에서 |
| **증분 동기화** | 전체를 다시 훑지 않고 새 항목만 가져오는 방식 | 최신순 순회 중 이미 아는 `yt_video_id`에 닿으면 멈춤. 전체 재스캔은 옵션 |

## 2. 자막·스크립트

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **스크립트(transcript)** | 영상의 말을 글로 옮긴 것. **세그먼트**(시작·끝·텍스트) 목록 | DB `transcripts` + `transcript_segments`. 전체 텍스트는 파생물 |
| **수동 자막(manual)** | 업로더가 직접 올린 자막. yt-dlp `subtitles` | 1순위. `source=manual` |
| **자동 자막(auto)** | 유튜브 음성 인식이 만든 자막. yt-dlp `automatic_captions` | 2순위. **원어 트랙**만 쓴다. `source=auto` |
| **원어 트랙 `-orig`** | 자동 자막 중 번역되지 않은 원본 언어 트랙. 키가 `ko-orig`처럼 `-orig`로 끝난다 | `ORIGINAL_CAPTION_SUFFIX = "-orig"`. 저장 시 언어는 `ko`로 정규화 |
| **번역 트랙** | 원어 자동 자막을 유튜브가 기계 번역한 것(`en`, `ja` …, 150개+) | 요청하면 **HTTP 429**가 나기 쉽다. 기본 꺼짐. 켜면 `source=translated` |
| **json3** | 유튜브 자막 포맷 중 하나. `events[]` 안에 `tStartMs`, `dDurationMs`, `segs[].utf8` | 타이밍이 가장 세밀해 원본으로 보존한다(`captions/<id>.<lang>.json3`) |
| **폴백(fallback)** | 1차 수단이 실패하면 2차 수단으로 넘어가는 것 | yt-dlp 자막 → youtube-transcript-api → Whisper 체인 |
| **정규화(normalize)** | 공백·특수문자 정리, 짧은 조각 병합 | DB에만 적용. 원본 파일은 건드리지 않는다. 규칙 버전을 `pipeline_version`에 동반 저장 |

## 3. 유튜브 접근 (yt-dlp 생태계)

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **yt-dlp** | 유튜브 등에서 영상·메타·자막을 받는 오픈소스 도구(Python) | 목록·메타·자막·오디오 전부. 버전 2026.08.19 |
| **PO 토큰(Proof-of-Origin Token)** | 유튜브가 "진짜 브라우저 요청"임을 증명하라고 요구하는 토큰 | 없으면 일부 자막·포맷이 조용히 빠질 수 있다. **bgutil** 제공자로 생성 |
| **bgutil-ytdlp-pot-provider** | PO 토큰을 만들어 yt-dlp에 넘기는 플러그인. Python 플러그인 + **Node 스크립트** 두 부분 | 스크립트 모드(`generate_once.js`)를 쓴다. pip만으로는 안 되고 Node 서버 디렉토리를 빌드해야 한다(T-001) |
| **JS 런타임 / EJS** | 유튜브 페이지의 자바스크립트 챌린지를 풀기 위해 yt-dlp가 필요로 하는 JS 실행기(Node·Deno) | `--js-runtimes node`. Node 24 사용. Deno 불필요 |
| **임퍼서네이션(impersonation)** | HTTP 요청을 특정 브라우저처럼 위장(TLS 지문 등). `curl_cffi` 필요 | 미설치 경고만 관측. 차단 시 P1에서 도입 판단 |
| **HTTP 429** | "Too Many Requests" — 서버가 요청을 거절 | 번역 자막 요청에서 즉시 발생. 대기 후 재시도(지수 백오프) |
| **레이트리밋 / 지터** | 요청 빈도 제한 / 요청 간격에 무작위성을 주는 것 | 네트워크 워커 1개, 간격 1~3초 지터 |
| **m4a / DASH** | AAC 오디오 컨테이너 / 스트리밍용 분할 포맷 | `bestaudio[ext=m4a]`로 오디오만 받는다. "DASH m4a" 경고가 나지만 PyAV가 읽는다 |

## 4. 음성 인식(STT)

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **STT(Speech-to-Text)** | 음성 → 텍스트 | 자막 없는 영상의 3순위 소스. `source=whisper` |
| **Whisper** | OpenAI가 공개한 다국어 음성 인식 모델 | 한국어 품질이 좋아 채택 |
| **faster-whisper / CTranslate2** | Whisper를 CTranslate2 런타임으로 옮겨 CPU에서 빠르게 돌리는 구현 | `SttEngine` 기본 구현. 모델은 HF Hub의 CT2 변환본 |
| **int8 양자화** | 모델 가중치를 8비트 정수로 줄여 메모리·속도를 개선 | `compute_type="int8"`. GPU 없음 |
| **모델 크기(small / medium / large-v3-turbo)** | 파라미터 수. 클수록 정확·느림 | 코어 1개 실측: small **3.05x**, turbo **0.86x**. 기본 small(보류 결정 2) |
| **x실시간(x realtime)** | 오디오 길이 ÷ 처리 시간. 1보다 크면 실시간보다 빠름 | 140초 오디오를 46초에 → 3.05x |
| **VAD(Voice Activity Detection)** | 음성이 있는 구간만 골라내기 | `vad_filter=True`(Silero). 무음 구간 건너뛰어 속도·환각 개선 |
| **beam size** | 디코딩 시 동시에 탐색하는 후보 수. 크면 정확·느림 | 기본 1(속도). P2에서 비교 |
| **환각(hallucination)** | 무음·잡음 구간에 모델이 없는 말을 만들어 내는 현상 | VAD + `condition_on_previous_text=False`로 억제 |
| **HF Hub / HF_HOME** | Hugging Face 모델 저장소 / 로컬 캐시 위치 환경변수 | 모델 1회 다운로드(small 464MB). Windows는 심볼릭 링크를 못 써 공간을 더 쓴다 → `HF_HOME`을 우리가 지정(T-002) |
| **PyAV** | ffmpeg 라이브러리를 내장한 Python 바인딩 | faster-whisper의 오디오 디코더. **ffmpeg 바이너리 불필요** |

## 5. 저장·작업

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **SQLite / WAL** | 파일 하나짜리 DB / Write-Ahead Logging(읽기·쓰기 동시성 개선 모드) | 기록 원본. `youtube_learner.db`, WAL, `busy_timeout` |
| **자연키(natural key)** | 데이터 자체가 가진 고유 식별자(대리키 아님) | `yt_channel_id`, `yt_video_id` |
| **upsert** | 있으면 갱신, 없으면 삽입 | 동기화 재실행 시 행이 늘지 않게 |
| **멱등성(idempotency)** | 같은 작업을 여러 번 해도 결과가 한 번 한 것과 같음 | 파이프라인의 필수 성질(CLAUDE.md 6절). 끊기고 다시 돌아가는 것이 정상 운영 |
| **작업(job) / 큐 / 워커** | 오래 걸리는 일의 단위 / 대기열 / 실행자 | Huey(SQLite 백엔드). 네트워크 워커 1 + STT 워커 1 |
| **Huey** | 가벼운 Python 작업 큐. Redis 없이 SQLite로 동작 | P2. Windows는 thread worker |
| **status 파일** | 단계 실행의 시작·성공·실패 기록(`status/<stage>_<run_id>.json`) | `run_context`가 남긴다 |
| **하류 덮어쓰기 금지** | 상류 산출물에서 만들어진 것을 직접 고치지 않는 원칙 | 원본 json3/Whisper 출력 → DB → 전체 텍스트 한 방향 |

## 6. 설계·방법론

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **Protocol (typing.Protocol)** | 상속 없이 "이 메서드들을 가지면 이 타입"으로 취급하는 구조적 인터페이스 | `VideoListSource`·`TranscriptProvider`·`SttEngine`·`Analyzer`. 테스트 fake를 상속 없이 만든다 |
| **DIP(의존성 역전)** | 상위 로직이 구체 구현이 아니라 추상(Protocol)에 의존 | 구현 선택은 조립 지점 한 곳(`api/app.py`, CLI `_run`) |
| **분석 슬롯** | 자동 요약·핵심 도출 기능을 나중에 끼울 자리 | `Analyzer` + 레지스트리(`NullAnalyzer`) + `analyses` 테이블 + API 501 + 화면 탭. v1 은 자동 분석은 자리만 |
| **수동 요약 흐름** | 사용자가 스크립트를 **복사**해 자기 AI 챗 서비스에서 요약을 받고 '요약 및 정리' 메뉴에 **붙여 넣어 저장**하는 것 | v1(P3). `analyses.analyzer_name = "manual"`. 자동 분석기와 같은 테이블·같은 화면, 출처로 구분 (scope 2.4절 v2) |
| **등급 A / B / C** | 테스트 전략 3등급 — 순수 로직(테스트 먼저, ≥90%) / 오케스트레이션(≥70%) / 탐색(검증 스크립트) | `CLAUDE.md` 3절 |
| **FR(Functional Requirement)** | 기능 요구사항 번호 | P0 = FR-1~, P1 = FR-101~ … 코드 docstring·테스트가 번호로 역참조 |
| **TechSpike(기술 검증)** | 프롬프트 작성 **전에** 외부 동작을 실제로 호출해 확인하는 단계 | `docs/internal/P{N}_검토서_TechSpike.md`. 참조 방법론의 "완성본 비교" 자리를 대신 |
| **보류 결정** | 지금 안 정하고 트리거·판정법·이정표와 함께 등재한 결정 | `CLAUDE.md` 1절 표(8건) |
| **SelfReview / Direct 리뷰** | 자체 점검 / 사용자가 직접 하는 리뷰(PR 아님) | Phase 종료 전 순서: SelfReview → 학습가이드 → Direct 리뷰 → 병합 |
| **verify_docs** | 문서 속 명령·경로·링크·표를 기계로 검사하는 스크립트 | `scripts/verify_docs.py`, pytest에 포함 |
| **check_env** | 작업 전 환경 검사(`==> READY`) | `scripts/check_env.ps1` → `python -m youtube_learner.cli.check_env` |
