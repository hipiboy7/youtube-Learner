# docs/internal/templates — 문서 골격

이 디렉토리는 Phase마다 반복해서 쓰는 문서의 **골격(템플릿)** 을 둔다. 참조 방법론에서는 이전 Phase 문서를 보고 따라 썼지만,
새 프로젝트에서 같은 구조를 재현하려면 명시적 골격이 필요해 추가했다 (기획서 1.2절 "문서 템플릿" 조정 항목).

## 사용법

1. 필요한 템플릿을 복사해 `CLAUDE.md` 9절 파일명 규칙(`[P<N>_]<DocType>_<Topic>.md`)에 맞춰 이름을 바꾼다.
2. 머리말 불릿 메타 블록을 채운다 (상위 문서·절번호, 사용 프롬프트, 규칙, 작성일, 작성 LLM, 상태/결과/결론).
3. `> 안내:`로 시작하는 인용 블록은 **작성 지침**이다. 채우고 나면 지운다.
4. `<…>`는 자리표시자다. 남겨두지 않는다.
5. 절 번호와 순서는 바꾸지 않는다 — `doc-consistency` 에이전트와 사람이 같은 자리에서 같은 내용을 찾을 수 있어야 한다.
   절을 추가할 때는 끝에 붙인다.

## 공통 규약 — 머리말 메타 블록

모든 문서는 `#` 제목 바로 아래에 **불릿 목록**으로 메타를 둔다 (YAML front-matter가 아니다).

```markdown
# P1 요구사항정의서 — ChannelListing

- 상위 문서: `docs/scope-definition.md` (v3) 2절·7절, `docs/설계서_Architecture.md` 2절
- 사용 프롬프트: `docs/prompts/phase1/channel-listing-v1.md`
- 규칙: `CLAUDE.md` 4절 1단계 산출물. 다음 산출물은 `docs/P1_설계서_ChannelListing.md`
- 작성일: 2026-09-20 / 작성 LLM: Fable 5.1
- 상태: 초안
```

- **상위 문서에는 버전과 절번호까지** 적는다. 상위가 개정되면 이 줄이 "어느 판을 보고 썼나"를 말해준다.
- 개정은 제자리에서 하고, 제목 아래에 `> **v2 개정 사유 (YYYY-MM-DD)**: …` 인용을 **최신순으로 누적**한다. 이전 판 서술을 지우지 않는다.
- FR 번호는 Phase별 번호대를 쓴다: P0 = FR-1~99, P1 = FR-101~199, P2 = FR-201~299 … (문서 사이에서 번호만 보고 Phase를 알 수 있게).
