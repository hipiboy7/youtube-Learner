## 수행 내용

1. 브랜치 생성·push(첫 push 는 GitHub 500 으로 실패, 재시도 성공). `fastapi`·`uvicorn` 설치(extras `api`).
2. 프로토타입 코드 `proto/` — yt.py(목록·메타·자막 json3·오디오·폴백), stt.py(faster-whisper), store.py(proto_* 테이블), app.py(FastAPI). 프로토타입 화면 코드 `App.tsx` 프로토타입 화면. 프로토타입 브랜치의 실행 스크립트 `dev_proto.ps1`.
3. 실측(`docs/internal/검토서_Prototype.md` 3절): 동기화 12+12건 2.9초 / 자막 스크립트 373 세그먼트 22초 / 한글 요약 저장·조회 / Whisper 79초 숏폼 124초(전사 ≈2.6x 실시간).
4. 장애 1건: CPU 97% 부하에서 bgutil 의 Node 검사(15초 제한)가 타임아웃 → 500 + stale pending. yt-dlp 인스턴스 재사용 + 네트워크 락 + 예외 전부 `failed` 기록 + 재시도 허용으로 해결(검토서 4절 1행 — P2 설계 인계).
5. 프론트 테스트 13건·빌드 통과, ruff 통과.

### 6. 사용자 피드백 반영 (같은 날 저녁)

- `.ps1` 한글 깨짐(T-005) → UTF-8 BOM.
- Gemini 요약 비교(URL 판 vs 스크립트 판) → 실제 자막과 대조, 결론·결정을 `docs/internal/qa/P3_질의응답_복사형식과요약비교.md` 에 기록.
- 복사 형식: 프롬프트 → 메타데이터 머리말 → [m:ss] 스크립트(기본 전부 켬), 프로토타입 코드 `copyText.ts`(테스트 8건). 프롬프트 편집·저장·복원(`proto_settings`, `GET/PUT/DELETE /proto/settings/summary_prompt`). 기본 프롬프트는 사용자 Gemini 프롬프트를 붙여넣기용으로 손봄.
- "저장 안 됨·복사 안 됨" 보고 → 잔존 uvicorn(옛 코드) + 조용한 복사 실패(T-006). 스크립트가 잔존 리스너 정리, `/health version`, 복사 폴백·사유 표시, 옛 백엔드 경고.
